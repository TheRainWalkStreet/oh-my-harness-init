# commits.md 模板

用于生成 `docs/standards/commits.md`。

````markdown
# 提交规范

## 规范来源

- 项目已有工具：{commitlint/changeset/semantic-release/待确认}
- 项目历史惯例：{从 git log 观察或待确认}
- 默认基线：Conventional Commits

## 提交信息格式

使用 `<type>(optional-scope): <summary>`。

默认 type：

- `feat`: 新功能。
- `fix`: 缺陷修复。
- `docs`: 文档变更。
- `refactor`: 不改变行为的重构。
- `test`: 测试相关。
- `chore`: 构建、依赖、工具、杂项。

## 提交粒度

- 单次提交围绕一个清晰意图。
- 不把格式化、重构、功能和文档大面积混在一起。
- 大型任务优先拆成可 review 的小提交。

## 分支命名

{如果项目已有规则，写项目规则；否则写待确认或建议格式。}

## PR 描述

PR 或最终说明包含：

- 变更摘要。
- 验证方式。
- 风险和回滚提示。
- 遗留问题。

## Review 前自检

- diff 是否只包含当前任务相关改动。
- 文档是否同步更新。
- 是否记录验证结果。
- 是否遗漏安全或配置风险。

## 禁止提交

- 密钥、账号、内部地址、真实用户数据。
- 无关格式化。
- 生成产物，除非项目明确要求提交。
- 未说明来源的大段外部文本。

## Agent 提交约束

- 提交说明必须基于实际 diff。
- 不编造测试、CI、发布或用户确认。
- 不替用户执行提交，除非用户明确要求。
````
