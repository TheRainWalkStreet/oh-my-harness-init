# 上下文策略：静态 vs 动态

## 静态上下文（存储在仓库中，始终可用）

| 制品           | 文件                              | 作用                                 |
|----------------|-----------------------------------|--------------------------------------|
| 导航地图       | `AGENTS.md`                       | Agent 入口点，约 100 行索引           |
| 层级规则       | `docs/architecture/LAYERS.md`     | 权威依赖层级                         |
| 规范模式       | `docs/golden-principles/*.md`     | DO/DON'T，每个 30-60 行              |
| 开发指南       | `docs/guides/*.md`                | 设置、测试、部署指南                 |
| 执行计划标准   | `docs/exec-plans/` 或 `PLANS.md`  | 复杂功能的计划模板                   |
| 约束           | Linter 规则 + 边界测试             | 机械化约束，不依赖 Markdown 说明     |

## 动态上下文（每次会话开始时探测）

| 信号           | 来源                                              | 作用                               |
|----------------|---------------------------------------------------|------------------------------------|
| 工作进度       | `git status` + `git log --oneline -10`            | 当前进行中的工作，上次停止的位置   |
| 代码健康       | LSP 诊断 / Linter 输出                            | 需要优先处理的问题                 |
| CI 状态        | 见下方"CI 状态信号"说明                           | 主分支是否健康？                   |
| 未完成任务     | 会话状态目录或项目任务跟踪器                     | 从上次会话恢复                     |
| 架构合规性     | 运行边界测试（如存在）                           | 是否有新的层级违规？               |
| 文档漂移       | 比较 docs/ 时间戳与 src/                          | 文档是否已过时？                   |
| 应用可观测性   | 应用日志、指标、追踪（如可用）                   | 运行时错误、性能问题               |

### CI 状态信号（按平台）

不同 CI 平台使用不同命令获取状态：

| CI 平台       | 状态查询命令                              | 备注                          |
|---------------|-------------------------------------------|-------------------------------|
| GitHub Actions | `gh run list --limit 3`                  | 需安装 GitHub CLI             |
| GitLab CI     | `glab ci status` 或查看 `.gitlab-ci.yml` | 需安装 GitLab CLI             |
| Gitee（码云） | 查看仓库 CI 页面，无官方 CLI              | 可通过 Gitee API 查询         |
| Jenkins       | `curl {jenkins-url}/api/json`            | 需 Jenkins 访问权限           |
| 无 CI 平台    | 本地运行 `make ci`                        | 查看 `references/ci-templates.md` |

## 核心区别

- **静态** = "规则是什么" → 会话之间答案不变
- **动态** = "当前状态是什么" → 每次必须重新探测

两者缺一不可。静态上下文提供地图，动态上下文提供地形。

## 优雅降级

并非所有动态信号都始终可用。对缺失的工具进行处理：

| 信号           | 不可用时                       | 降级方案                                  |
|----------------|--------------------------------|-------------------------------------------|
| LSP 诊断       | 没有 LSP 服务器运行             | 改用 Linter CLI                           |
| CI 状态        | 无 CLI 工具 / 非支持平台        | 检查最近 CI 配置文件，跳过远程状态查询    |
| 会话状态       | 无会话状态目录（平台专属功能）  | 跳过，标注为全新会话；勿假定某特定目录存在 |
| 边界测试       | 尚未创建                       | 标注：将在阶段 3 创建                     |
| 应用可观测性   | 无日志/指标访问权限             | 跳过，标注不可用                          |

> **说明：** 某些平台（如 oh-my-claudecode 插件）会在特定路径（如 `.omc/state/`）维护会话状态。若你使用的是原生 Claude Code、Cursor 或 Codex，该路径不存在，直接跳过此信号即可。
